# Translating a garden app

Translation lives in each app, not in flora. flora's part is small: every component that
shows its own words takes a `labels` prop, and `LocaleToggleButton` is the language picker.
Everything else is the same handful of files in every app, set up as below. There is no
i18n library; reach for one (use-intl, MIT) only when an app needs a third language or a lot
of plurals.

## Dictionaries

```
src/i18n/en.json   source of truth
src/i18n/es.json   same keys, Spanish
```

Group keys by surface (`auth.signIn.submit`, `kitchen.start`) and keep a `flora` section for
the labels you pass to flora components. Type Spanish against English, so a missing key
fails the build:

```ts
import en from './en.json';
import es from './es.json';

export type Dict = typeof en;
export const dictionaries: Record<Locale, Dict> = { en, es };
export const locales = ['en', 'es'] as const;
export type Locale = (typeof locales)[number];
```

User data (menu items, project names) is never in a dictionary.

## Placeholders, plurals, formatting

Copy these rather than importing them:

```ts
export const format = (s: string, vars: Record<string, string | number>) =>
  s.replace(/\{(\w+)\}/g, (_, k) => String(vars[k] ?? `{${k}}`));

// "{count} order" / "{count} orders" as orders_one / orders_other
export const plural = (locale: Locale, n: number) =>
  new Intl.PluralRules(locale).select(n) === 'one' ? 'one' : 'other';

export const matchLocale = (candidates: readonly string[]): Locale =>
  candidates
    .map((c) => c.slice(0, 2).toLowerCase())
    .find((c): c is Locale => (locales as readonly string[]).includes(c)) ??
  'en';
```

Numbers, money and dates go through `Intl.*` with `undefined` as the locale, so they follow
the device's regional settings. The app's language alone is the wrong input: `es` formats
money the way Spain does (`12,50 US$`), not the way Mexico does (`$12.50`).

## Storing the choice

- **Server-rendered (Next):** a `locale` cookie, set by a server action that is passed
  straight to `LocaleToggleButton` as `onChange`. Setting the cookie re-renders the page.
  Read it with `cookies()`, then fall back to `Accept-Language`, then `en`. Pages that read
  it become dynamic.
- **SPA (Vite):** `localStorage['<app>:locale']`, read in try/catch, falling back to
  `navigator.languages`, then `en`. Keep it in a small provider with a `useT()` hook.

Either way, set `lang` on `<html>` to the active locale.

## Passing strings down

Pages and route roots look up the dictionary and pass a section down as a prop:
`<SignInForm t={dict.auth.signIn} />`. Shared components never read a global. JSON stays
plain strings, so a server component can hand it to a client component.

## flora labels

Each flora component that has its own words exports a `<Name>Labels` type and renders
English unless told otherwise:

```tsx
<DialogProvider labels={t.flora.dialog}>…</DialogProvider>
<ThemeToggleButton labels={t.flora.theme} />
<CopyableText label={t.clientId} value={id} labels={t.flora.copy} />
```

Pass only what you translate; the rest stays English.

## Errors

Servers return a stable `error` code; the UI shows `t.errors[code] ?? t.errors.generic`.
A server's `message` is detail for developers and is never shown. Keep a
`t.errors.network` for when the request never reached the server.
